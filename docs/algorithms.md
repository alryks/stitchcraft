# Основные алгоритмы проекта

Проект проходит изображение через несколько этапов:

```text
изображение
  → подготовка и карта важности
  → уменьшение цветовой гаммы
  → подбор цветов нитей
  → очистка мелких областей
  → смешанные цвета и типы стежков
  → цветовые участки
  → шов назад иголку
  → материалы и метрики
  → маршруты вышивания
```

Простые преобразования пользовательских параметров, например перевод сантиметров в количество крестиков, здесь не описываются.

## 1. Подготовка изображения и карта важности

**Назначение.** Сохранить контуры и заметные детали при уменьшении исходной картинки до размера схемы.

**Идея.** Изображение приводится к RGB с учётом прозрачности и уменьшается фильтром Lanczos. Затем для каждого пикселя вычисляются границы Canny и локальные изменения яркости через оператор Лапласа. Их объединение образует карту важности: на значимых границах применяется мягкое усиление резкости, а при последующей очистке такие клетки защищаются от замены.

**Этап.** Подготовка входного изображения перед квантизацией цветов.

**Файл.** `backend/app/processing.py`, функции `_prepare_image` и `_dimensions`.

## 2. Кластеризация цветов методом k-means

**Назначение.** Ограничить число оттенков, чтобы схема оставалась читаемой и соответствовала выбранному числу цветов.

**Идея.** Пиксели переводятся из RGB в CIELAB и разбиваются на заданное число кластеров. Центр кластера задаёт один усреднённый оттенок. Фиксированное начальное состояние делает результат воспроизводимым для одинаковых входных данных.

**Этап.** После подготовки изображения, до подбора нитей.

**Файл.** `backend/app/processing.py`, функция `_quantize_lab`.

## 3. Подбор ближайших цветов палитры

**Назначение.** Заменить абстрактные оттенки кластеров реальными цветами нитей DMC или Anchor.

**Идея.** Для каждого цвета схемы считается расстояние CIEDE2000 до каждого цвета выбранной палитры, и берётся минимум. CIELAB и CIEDE2000 учитывают особенности человеческого восприятия лучше, чем расстояние между RGB-координатами.

**Этап.** Сразу после кластеризации.

**Файлы.** `backend/app/color.py` (`rgb_to_lab`, `delta_e`, `match_palette`), `backend/app/palettes.py`, `palettes/dmc.json`, `palettes/anchor.json`.

## 4. Удаление мелких цветовых областей

**Назначение.** Убрать одиночные клетки и мелкий шум, который плохо подходит для вышивания.

**Идея.** Для каждой пары цветов строятся связные компоненты по четырём соседям. Если компонент меньше заданного порога, алгоритм оценивает цвета соседних клеток. Замена выбирается по ошибке цвета, частоте соседнего оттенка и карте важности. Клетки на важных границах получают защиту и сохраняются.

**Этап.** После подбора цветов и перед построением участков.

**Файл.** `backend/app/regions.py`, функции `components` и `reduce_confetti`.

## 5. Поиск смешанных цветов

**Назначение.** Представить оттенки, для которых одного цвета нити недостаточно.

**Идея.** Для наиболее часто используемых цветов перебираются пары. Средний цвет пары сравнивается с исходным по CIEDE2000. Смешанный цвет оставляется только тогда, когда ошибка уменьшается больше заданного порога; слишком маленькие области смеси удаляются.

**Этап.** После подбора основных нитей, до группировки областей.

**Файлы.** `backend/app/color.py`, функция `apply_blends`; вызов выполняется из `backend/app/processing.py`.

## 6. Выбор типа стежка

**Назначение.** Использовать полукрест на важных границах, где он лучше передаёт тонкую деталь.

**Идея.** По умолчанию клетка получает полный крест. Если карта важности выше адаптивного порога и режим полукрестов включён, выбирается одно из двух направлений диагонали. Направления чередуются по координатам, чтобы соседние полукресты не образовывали заметную однообразную полосу.

**Этап.** После очистки цветов и смешанных оттенков.

**Файл.** `backend/app/processing.py`, формирование поля `stitches`.

## 7. Построение цветовых участков

**Назначение.** Сгруппировать соседние клетки одного участка для отображения схемы и расчёта маршрута.

**Идея.** Клетки объединяются по паре `(основной цвет, вторичный цвет)` и обходятся поиском в ширину по четырём направлениям. Для каждого участка сохраняются клетки, границы, цвета и типы стежков.

**Этап.** После окончательного назначения цветов и стежков.

**Файл.** `backend/app/regions.py`, функция `build_regions`.

## 8. Построение шва назад иголку

**Назначение.** Добавить контурные линии, которые подчёркивают границы объектов на печатной и экранной схеме.

**Идея.** Кандидаты возникают на границе соседних областей с различными цветами. Слабые или фоновые переходы отбрасываются, а карта важности расширяется вокруг сильных границ. Параллельные дубли подавляются, соседние отрезки соединяются, а получившиеся линии упрощаются алгоритмом Дугласа–Пекера (`approxPolyDP`). В конце удаляются дубли и пересекающиеся отрезки, затем применяется ограничение их общего числа.

**Этап.** После построения цветовых участков и до формирования результата схемы.

**Файл.** `backend/app/processing.py`, функции `_backstitch`, `_edge_trails`, `_suppress_parallel_edges` и `_proper_intersection`.

## 9. Расчёт материалов

**Назначение.** Оценить расход канвы, иглы и мулине по готовой схеме.

**Идея.** Длина нити складывается из длин стежков с учётом их типа, числа рабочих нитей и вторичного цвета в смешанных стежках. Добавляется запас, а количество мотков округляется вверх по длине одного мотка 8 м. Игла выбирается по ближайшему подходящему номеру для выбранной плотности канвы.

**Этап.** После генерации схемы и участков.

**Файлы.** `backend/app/materials.py` (`select_canvas`, `calculate_materials`) и `backend/app/canvas.py` (`CANVASES`, `needle_for_count`).

## 10. Построение маршрута иглы

**Назначение.** Сформировать удобный порядок стежков и разделить его на отрезки, которые помещаются в рабочую длину нити.

**Идея.** Клетки обходятся «змейкой» по строкам. Для английского, датского и смешанного метода используются разные правила переходов. Длина шага зависит от типа стежка и метода; разрешены горизонтальные, вертикальные и короткие диагональные переходы. При нехватке доступной длины создаётся новый отрезок с учётом хвостов, загиба и запаса нити.

**Этап.** После создания схемы; для всех областей запуск выполняется автоматически.

**Файлы.** `prolog/planner.pl`, `prolog/movement.pl`, `prolog/methods.pl`, `prolog/thread.pl`; автоматический запуск — `frontend/src/stitchcraft/api.cljs`.

## 11. Метрики качества

**Назначение.** Отдельно оценить точность цветов и сохранность структуры изображения.

**Идея.** Средняя Delta E — средняя цветовая ошибка между исходным и подобранным цветом, поэтому меньшее значение лучше. SSIM сравнивает структурное сходство подготовленного изображения и изображения, собранного из основных цветов схемы, поэтому большее значение лучше. Эти метрики оценивают изображение, а не удобство маршрута или точность расхода материалов.

**Этап.** После построения схемы, вместе с итоговым результатом генерации.

**Файл.** `backend/app/processing.py`, расчёт `metrics` в `generate_pattern`.
